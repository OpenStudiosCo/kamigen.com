# Known limitations

- Rectangular / rounded panels only (no arbitrary panel shapes yet).
- SVG assets are referenced as nested images; unsupported SVG features are listed in `SVG_SUPPORT.md`.
- SVG page export keeps nested artwork as references and reports limitations (e.g. pulse glow → still appearance).
- Character SVGs under `new/src/assets/characters/` are stylised brand/wiki art, not full comic lettering pages.
- Editor chrome (handles, guides) is SVG-overlay only in the editor; reader/export modes omit it.
- Authoring server is localhost-only and is not part of the deployed site.
- No automatic git commit/push/deploy.
- Page 8 still has no layered master in `comics-sources/` (Issue 01 sources start at page 22). Crops remain comparison-only; editable Affinity import is demonstrated on **page 124** (`page_124_editable.json`). See `SOURCE_MANIFEST.md`.
- Jim production asset is `char_jim_artwork` (groupedSvg from actual `Jim.svg` paths, one articulated arm). The geometric cutout (`char_jim_poseable`) is legacy experiment only.
- Jim shoulder paint order uses inverse-shirt mask + `arm_L_under` sync (`prep/PREP.md`); FK nesting ≠ paint order.
- Jim has no expression variants in source — expression controls are withheld until alternate face paths exist (`prep/PREP.md`).
- VectorCraft opens Affinity/AI locally; many Issue 05 `.afdesign` files are truncated ~12MB stubs; AI editing-data layers are blocked when symbols are present.
- Affinity `FilB` bitmap/pattern fills are emptied on VC import — page 124 recovers clothing appearance via Affinity Characters raster clips (`PAGE_124_DISCREPANCY.md`).
- Comic fonts are available (`art/comics/library/fonts/` + system fontconfig). Use family names `Laffayette Comic Pro`, `Cardenio Modern`, `Bisaya MBF (ink)` on dialogue layers.
- Wardrobe / prop variants are not first-class on poseable rigs.
- Screentones/hatches are not generated by the editor.
